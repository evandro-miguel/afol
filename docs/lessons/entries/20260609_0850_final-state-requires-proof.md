# Final-State Claims Require Proof Artifacts, Not Waivers

## Context

During MVP finalization gaps session, specs marked `final` still had real
implementation gaps: missing update apply, stubbed file archive, narrow
local-state scope. Some gaps were waived rather than resolved.

## Lesson

`final` must mean proven, not waived. Release and public claims need
artifact-level proof. Scope gaps must become explicit tasks rather than
implicit waivers.

## Prevention

- Treat `final` specs as requiring executable proof, not status claims.
- Convert waivers to explicit tasks with scope and timeline.
- Release/public claims must be tied to platform-verified evidence.
